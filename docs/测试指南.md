# 测试指南

本指南聚焦“一键启动 + SQL Server 初始化”相关的自测与回归点，适用于交付验收与日常开发自检。

## 自测环境

- 启动方式：`docker compose up -d`
- 关键端口：前端 `3665`、后端 `8665`、SQL Server `1433`

## 冒烟测试（必须通过）

### 1) 容器健康状态

```bash
docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}' | grep jeecg-
```

预期：`jeecg-sqlserver` / `jeecg-redis` / `jeecg-backend` / `jeecg-frontend` 均为 `Up`，`jeecg-sqlserver-init` 最终为 `Exited (0)`。

### 2) 数据库已初始化

```bash
docker exec jeecg-sqlserver /opt/mssql-tools18/bin/sqlcmd -S localhost -U sa -P "${MSSQL_SA_PASSWORD:-Supcon1304}" -C -d temp1218 \
  -Q "SELECT COUNT(1) AS user_count FROM sys_user;"
```

预期：返回结果为正数（示例环境为 4）。

### 3) 前端可访问

浏览器打开 `http://localhost:3665`，预期加载登录页。

### 4) 后端可访问

浏览器访问 `http://localhost:8665`（或前端发起登录请求），预期后端无数据库连接异常日志。

## 回归测试（建议）

### 1) 登录与权限

- 使用 `admin/123456` 登录
- 进入首页后打开菜单、列表、详情页面，确认路由与权限控制正常

### 2) Redis 依赖

- 登录后保持会话与菜单加载正常
- 查看后端日志中不应出现 Redis 连接失败

### 3) SQL Server 兼容性

- 检查典型业务表 CRUD（例如用户、字典、组织机构等）
- 抽查包含大字段/JSON 字段的表写入与查询

## 已知差异与风险点

- 初始化阶段跳过外键与唯一约束（以保证全量初始化稳定性），依赖应用层校验；如生产环境需要强约束，需补充数据清洗与约束回补。
- MySQL 中的 `varchar(>4000)` 被映射为 `nvarchar(max)`，在 SQL Server 中对索引/排序存在限制，需结合具体表结构评估。


## 设备档案与附件（device 模块）

前置：已执行 `db/device/device_archive_sqlserver.sql`，重新登录后可见“设备管理 → 设备档案”。

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| 设备增改查 | 新增设备（编号/名称必填）→ 编辑 → 列表查询 | 保存成功，列表与详情字段正确；编号重复时数据库唯一约束报错有提示 |
| 附件上传 | 详情抽屉附件区选择类型后上传图片/PDF/文档 | 上传成功，列表出现记录，展示类型、文件名、大小、上传人（真实姓名）、上传时间 |
| 类型/大小限制 | 上传 `.exe` 或超过 50MB 文件 | 前端拦截并提示，不产生记录 |
| 附件删除确认 | 点击附件“删除” | 弹出“确认删除该附件？”，取消不删除；确认后记录消失，物理文件被清理 |
| 设备删除级联 | 对有附件的设备执行删除 | 二次确认后设备删除；`device_attachment` 中对应记录为 0（应用事务 + 外键 CASCADE 双保险） |
| 批量删除级联 | 勾选多台（含带附件设备）批量删除 | 确认后全部删除，关联附件记录同步删除，无孤儿记录 |
| 越权类型 | 未授权角色访问 `/device/**` 或上传 | 按菜单按钮授权控制（admin 默认可用） |

SQL 快速核验（应返回 0）：

```bash
docker exec jeecg-sqlserver /opt/mssql-tools18/bin/sqlcmd -S localhost -U sa -P "${MSSQL_SA_PASSWORD:-Supcon1304}" -C -d temp1218 \
  -Q "SELECT COUNT(1) AS orphan_count FROM device_attachment a WHERE NOT EXISTS (SELECT 1 FROM device_archive d WHERE d.id = a.device_id);"
```
